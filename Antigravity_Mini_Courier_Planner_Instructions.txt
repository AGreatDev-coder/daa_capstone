ROLE ============================================================

The project is an individual, coding-based DAA assignment. The purpose
is to demonstrate the implementation and understanding of: 1. A sorting
algorithm for parcel prioritization. 2. Dynamic Programming using the
0/1 Knapsack problem for vehicle packing. 3. Dijkstra’s algorithm for

easy-to-demonstrate command-line application unless there is a strong
reason otherwise.

============================================================ 2. PROBLEM
TO SOLVE ============================================================

Build a prototype courier-planning system that accepts parcel
information and delivery locations, then produces: - Parcels ordered by
delivery priority/deadline. - An optimal parcel selection for one trip
under a vehicle weight capacity, using 0/1 Knapsack DP. - Shortest paths
between delivery points using Dijkstra’s algorithm. - An overall
delivery visit sequence using the Nearest Neighbor TSP approximation. -
Total route distance and performance measurements for major algorithmic
steps.

The system should make it easy to understand how each algorithm
contributes to the final courier plan.

============================================================ 3.
FUNCTIONAL REQUIREMENTS
============================================================

A. INPUT / DATA MODEL

Create sample datasets for parcels and locations.

Each parcel should contain, at minimum: - parcel_id -
destination/location_id - weight - value (or clearly defined delivery
benefit) - priority - deadline

Each location should have: - location_id - location_name

Represent roads/routes as a weighted graph. Each edge must contain a
non-negative distance. Use a consistent distance unit, preferably
kilometres.

Validate input: - Weight and capacity must be positive or zero as
appropriate. - Parcel value must be non-negative. - Distances must be
non-negative because Dijkstra’s algorithm is being used. - Location IDs
referenced by parcels and graph edges must exist. - Handle empty data
and invalid user input gracefully.

Use JSON or another simple, documented data format for sample data. Keep
sample data separate from algorithm code.

B. PARCEL PRIORITIZATION — SORTING

Implement a sorting algorithm to arrange parcels by priority and/or
delivery deadline.

Recommended primary implementation: Merge Sort.

Define and document the sorting rule clearly. For example: - Higher
priority first. - For equal priority, earlier deadline first. - Use
parcel ID as a final deterministic tie-breaker if needed.

Do not rely only on Python’s built-in sorted() for the required
algorithm implementation. The sorting logic itself must be implemented
and demonstrated.

Show the sorted parcel list in the output.

C. VEHICLE PACKING — 0/1 KNAPSACK USING DYNAMIC PROGRAMMING

Implement 0/1 Knapsack using a DP table.

Inputs: - Parcels (weight and value/benefit). - Vehicle maximum weight
capacity.

Rules: - A parcel is either selected completely or not selected. - A
parcel cannot be selected more than once. - Total selected weight must
not exceed capacity. - Maximize total selected value/benefit.

Return and display: - Selected parcel IDs. - Total selected weight. -
Total selected value. - Vehicle capacity. - DP table or a readable
representation/evidence of the DP computation.

Explain the DP state, recurrence, base case, and reconstruction of
selected parcels in the documentation.

Important integration rule: The assignment asks for parcels to be
prioritized and then selected for one delivery trip. Make the
relationship explicit in the program. Do not silently claim that sorting
changes the mathematical optimum of 0/1 Knapsack. Use the sorted parcel
list as the consistent input order for the DP implementation, and
explain that Knapsack determines the maximum-value feasible subset.

D. ROUTE GRAPH — DIJKSTRA’S ALGORITHM

Build a weighted, undirected graph by default, unless the data model
explicitly requires directed roads.

Implement Dijkstra’s algorithm yourself. Do not replace the required
implementation with a library shortest-path function.

The implementation should: - Accept a source node. - Calculate shortest
distances to all reachable nodes. - Store predecessor information. -
Reconstruct a shortest path to a requested destination. - Handle
unreachable destinations clearly.

Display shortest path and total distance for relevant delivery
locations.

E. COMPLETE DELIVERY ROUTE — NEAREST NEIGHBOR TSP APPROXIMATION

Implement the Nearest Neighbor heuristic for a complete delivery tour.

Expected behavior: 1. Start from the warehouse/depot. 2. Select the
nearest unvisited delivery location. 3. Mark it visited. 4. Repeat until
all required delivery locations have been visited. 5. Return to the
warehouse/depot if a return trip is part of the defined scenario.

Important: - Nearest Neighbor is an approximation/heuristic; do not
claim it always finds the optimal TSP route. - Use Dijkstra
shortest-path distances between locations as the distance matrix for the
TSP visit-order calculation when the road graph does not directly
contain every pair of locations. - Preserve the actual shortest path
segments when displaying the final route, not just the order of location
names. - Handle disconnected graphs. If a required location cannot be
reached, report it clearly rather than inventing a route. - Avoid
visiting the same delivery location multiple times except where
shortest-path segments naturally pass through an already visited node. -
Clearly state whether the final route returns to the warehouse.

Display: - Ordered delivery locations. - Expanded route/path, where
possible. - Total route distance in kilometres. - Any unreachable
locations or route limitations.

============================================================ 4. PROJECT
INTEGRATION ============================================================

Create one main application entry point that connects all modules in
this order:

1.  Load and validate parcel/location/graph data.
2.  Display parcel information.
3.  Run Merge Sort to prioritize parcels.
4.  Run 0/1 Knapsack to select parcels within vehicle capacity.
5.  Identify the delivery locations associated with selected parcels.
6.  Run Dijkstra to calculate shortest-path distances between relevant
    locations.
7.  Run Nearest Neighbor TSP approximation to determine the delivery
    visit order.
8.  Expand the visit order into actual shortest path segments.
9.  Display the complete courier plan.
10. Run performance tests and show or save results.

If multiple selected parcels have the same destination, visit that
destination only once in the route.

Make the depot/warehouse configurable in the sample data or application
settings.

============================================================ 8. TESTING
AND CORRECTNESS
============================================================

Create test cases for every algorithm, including edge cases.

Sorting: - Already sorted input. - Reverse-sorted input. - Equal
priorities/deadlines. - Empty and single-item input.

Knapsack: - Empty parcel list. - Zero capacity. - Parcel heavier than
capacity. - Multiple parcels with equal values. - Case where selecting
no parcel is valid.

Dijkstra: - Simple connected graph. - Multiple possible paths. -
Unreachable node. - Single node. - Zero-weight edge, if supported.

TSP Nearest Neighbor: - One delivery location. - Multiple locations. - A
graph where the heuristic is not optimal. - Disconnected/unreachable
locations. - Return-to-depot behavior.

Verify: - Selected parcel weight never exceeds capacity. - Every
selected parcel appears at most once. - Every required reachable
delivery location is included in the route. - Route distance equals the
sum of its path-segment distances. - No negative edge weights are
accepted for Dijkstra. - Output is deterministic for the same input.

Use unit tests (preferably unittest or pytest). Include commands to run
them.
